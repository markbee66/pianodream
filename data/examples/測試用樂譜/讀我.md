# 測試用樂譜

分兩類：**有標準答案的**（量得出正確率）與**沒有標準答案的**（量得出「認不認得出來」）。

## 一、有標準答案

來自 [Mutopia Project](https://www.mutopiaproject.org)，全部**公有領域**。
每一首都有 PDF 與 MIDI，兩者出自同一份 LilyPond 原始碼，
所以 **MIDI 就是那份 PDF 的正確答案**：

| 檔案 | 內容 | 譜表 |
|---|---|---|
| `alkan_prelude1.pdf` / `.mid` | Alkan《前奏曲》Op. 31 No. 1　1 頁、379 音 | 大譜表 |
| `andre_sonatine.pdf` / `.mid` | Johann André《小奏鳴曲》Op. 34 I　2 頁、571 音 | 大譜表 |
| `bach_polonaise.pdf` / `.mid` | Bach《波蘭舞曲》BWV Anh. 117a | 大譜表 |
| `bach_chorale510.pdf` / `.mid` | Bach 聖詠 BWV 510 | 大譜表 |
| `bach_chorale511.pdf` / `.mid` | Bach 聖詠 BWV 511 | 大譜表 |
| `bach_aria515.pdf` / `.mid` | Bach 詠嘆調 BWV 515 | 大譜表 |
| `cpe_flute_solo.pdf` / `.mid` | C.P.E. Bach 長笛獨奏奏鳴曲 Wq 132 | **單行譜** |
| `bwv1013_flute.pdf` / `.mid` | Bach 長笛組曲 BWV 1013 | **單行譜** |

**刻意收了一半單行譜。** 原本手上的樣本全是鋼琴大譜表，唯一的單行譜是
〈うまぴょい伝説〉—— 樣本這麼偏，改小節線偵測時很容易調成「只對那一首有效」。
單行譜的小節線只有 4 個行距高（大譜表有 15–16），是完全不同的狀況。

## 二、沒有標準答案（2026-08-13 加入）

沒有參考答案就量不出正確率，但每一份都在測一種**特定的失敗方式**，
而且每一份都真的抓到過 bug。詳見 `工作紀錄.md` 2026-08-13 那兩篇。

| 檔案 | 測什麼 | 結果 |
|---|---|---|
| `清晰譜1.png` | 密集的浪漫派織體 | 只認出 11 小節，Gate B 信心 0.36 —— homr 的弱點 |
| `污漬(鉛筆筆記).png` | **跟上面同一頁**，但畫滿鉛筆紅筆註記 | 對照上面只剩 **81.0%**，而且是**多認**不是漏認 |
| `清晰譜2(士兵進行曲).png` | 乾淨的初級曲（Schumann） | 33 小節 / 212 音，信心 **0.98**，已加成可以玩的曲子 |
| `透明背景1-4.png` | **透明背景的 PNG** | 修掉 alpha bug 之前完全認不出來，之後信心 0.97–1.00 |

`清晰譜1` 與 `污漬` 是**有對照組的實驗**：同一頁樂譜，一份乾淨一份被畫滿，
所以乾淨版可以當另一份的參考答案。量出來手寫註記大約值 19 個百分點，
而且註記的筆畫會被當成音符讀進去 —— **認出來的音變多，不是變少**，
那種錯誤從外表完全看不出來。

## 怎麼量

```powershell
.\.venv\Scripts\python.exe tools\omr_accuracy.py `
    data\examples\測試用樂譜\andre_sonatine.pdf `
    data\examples\測試用樂譜\andre_sonatine.mid
```

流程：PDF 逐頁轉 300 DPI 圖 → OMR → 合併 → 跟標準答案比對。

## 目前的結果（2026-08-13，加上前處理之後）

`tools/omr_bench.py` 會把同一份 PDF 用 `tools/photo_sim.py` 弄成手機拍的樣子，
再跑一次 —— 這樣「照片的正確率」也有標準答案可以對。

| 拍攝條件 | 直接辨識 | 加上前處理 |
|---|---|---|
| 300 DPI 排版檔 | 94.7% / 100% | **100% / 100%** |
| 拍得很好 | 100% / 100% | **100% / 100%** |
| 隨手拍 | 99.8% / 99.2% | **100% / 100%** |
| 拍得很差 | 13.0% / 10.0% | 31.5% / 3.2% |

（André / Alkan，對齊後配對率。）

**只要照片還堪用，前處理後就是 100%。**「拍得很差」是紙只佔畫面 66%、
失焦達 0.38 個行距，兩邊都救不回來。**這些仍然是模擬照片，不是真的手機拍的。**

## 兩個指標為什麼要分開看

| 指標 | 看什麼 |
|---|---|
| **音高組成** | 兩邊的音高多重集合重疊多少。跟時間無關，純粹看「該有的音有沒有被認出來」 |
| **對齊後配對率** | 用 parangonar 做音符級對齊，算配對 / 漏認 / 多認。看得出音符的前後關係對不對 |

**「依序逐音比對」故意不用** —— 和弦內的音序本來就是任意的，而且只要前面漏一個音，
後面全部錯位，那個數字會低到毫無意義（實測 André 那首會變成 22%，
但實際上只漏了 30 個音）。
